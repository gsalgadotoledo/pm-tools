# 61 - User Stories y Acceptance Criteria

## Formato de User Story

> **Como** [tipo de usuario], **quiero** [accion], **para que** [beneficio].

### Por Que Este Formato?

- PM escribe el **que** y el **por que**, NO el como
- Evita decirle a los ingenieros como hacer su trabajo

## Formato de Acceptance Criteria

> **Dado que** [contexto], **cuando** [accion], **entonces** [resultado esperado].

### Ejemplo

1. *Dado que soy un usuario y hago click en el boton de agregar foto en DM, se me presenta un pop-up para elegir archivo, puedo subirlo y ver un preview.*
2. *Dado que subi una foto, cuando hago click en enviar, la imagen se envia por DM y aparece en el chat.*

## Donde Viven

```
Herramienta de PM (Jira, etc.)
  └── Epic
       └── Ticket
            ├── User Story
            ├── Acceptance Criteria
            └── Wireframes/Disenos
```

## El Flujo de Trabajo

```
Backlog → Sprint Planning → Sprint (To Do → In Progress → QA → Done) → PM prueba → Aprobado → Released
```
