# 29 - Feature Table para un Feature Propuesto (Ejemplo Udemy)

## Dos Usos de Feature Tables

| Uso | Cuando |
|---|---|
| **Post-mortem** (ejemplo GoPro) | Comparar tu producto existente vs competidores — que mejorar? |
| **Feature propuesto** (esta nota) | Antes de construir — que debemos incluir basado en lo que los competidores ya ofrecen? |

## La Tabla: Feature de Discusiones Grupales

| Factor | Skillshare | Coursera | Udacity | Lynda | Udemy |
|---|---|---|---|---|---|
| **Tiene discusiones?** | Si, integrado | Si, integrado | Si, standalone | No | Si, integrado |
| **Marcas de tiempo** | Si (leccion + tiempo) | No | No | — | No (solo ref. leccion) |
| **Features de engagement** | Like, Reply | Upvote, Follow, Reply | Reply, Favorite, Link, Bookmark, Like | — | Like, Reply, Search |
| **Ubicacion** | Below fold | Below fold | Tab separado | — | Prominente (1/3 pantalla, derecha) |
| **Publicar imagenes** | Si | Si (rich text + HTML) | Si | — | Si |

## Preguntas Estrategicas

1. Debemos intentar **ganarles en todas las categorias**?
2. Debemos **depriorizar** porque no podemos ganar?
3. Debemos simplemente **lanzar lo basico** para poder decir que lo tenemos?
4. Que tan lejos estamos de ser **los mejores** en esta categoria?
5. **Deberia importarnos** este feature?

## Punto Clave: Dos Tipos de Feature Tables

```
Tabla a nivel producto:  Tu vs competidores en TODO
                         → "Somos competitivos en general?"

Tabla a nivel feature:   Un feature especifico entre competidores
                         → "Que debemos construir y que tan bueno debe ser?"
```

Ambas son valiosas. Usa la de producto para estrategia, la de feature antes de construir.
