# 60 - De Vision a Epics: La Jerarquia del PM

> Nuevo capitulo: Construyendo Productos Dia a Dia

## La Jerarquia

```
Vision (CEO/Fundadores)
  └── Metas (Ejecutivos → definidas como metricas)
       └── Iniciativas (Equipos de management)
            └── Releases (features agrupados lanzados en una fecha)
                 └── Epics (agrupacion de features/funcionalidad)
                      └── User Stories + Acceptance Criteria
```

## Ejemplo

| Nivel | Ejemplo |
|---|---|
| **Vision** | Ser la plataforma #1 de aprendizaje de idiomas global |
| **Meta** | Aumentar nuevos usuarios en 5% este ano |
| **Iniciativa** | Traducir el producto a 3 nuevos idiomas |
| **Release** | Release de febrero: los 3 idiomas disponibles |
| **Epic** | Traducir app a espanol |
| **User Story** | "Como usuario, quiero cambiar el idioma de la app a espanol para poder usarla en mi idioma nativo" |

## Que es un Epic?

- Jerga de PM para una **agrupacion de features/funcionalidad** a construir
- El ladrillo fundamental con el que construyen los PMs
- Equipos tipicamente construyen **3-5 epics por trimestre**
- Toma **mas de un sprint** (si es mas corto → solo una user story)
- NO siempre es visible al usuario (ej: "migrar base de datos" es un epic tambien)

## Epic Spec Sheet (Documento de Requisitos)

| Seccion | Responsable | Contenido |
|---|---|---|
| **Introduccion** | PM | Que, por que, metricas a mejorar, MVP vs estado ideal, links de soporte |
| **Requisitos de Producto** | PM | Funcionalidad detallada necesaria |
| **Requisitos de Diseno** | Disenador + PM | Wireframes, prototipos, specs visuales |
| **Requisitos de Ingenieria** | Ingenieros | Necesidades de DB, API endpoints, escalamiento, dependencias tech |
