# 63 - Roadmapping

## La Verdad Incomoda

Los roadmaps son **casi siempre inexactos** — y esta bien.

Si haces Agile, no puedes predecir 3-4 meses adelante.

## Dos Tipos de Roadmaps

### 1. Basado en Tiempo (Trimestral)

```
Q1: Feature A, Feature B
Q2: Feature C, Iniciativa D
Q3: Feature E, Feature F
```

**Cuando funciona**: Empresas B2B con deadlines de ventas ("el cliente necesita esto para febrero").

### 2. Basado en Prioridad (Ahora/Siguiente/Despues)

```
| AHORA (semanas)  | SIGUIENTE (meses) | DESPUES (algun dia) |
|------------------|--------------------|---------------------|
| Epic A           | Epic D             | Epic G              |
| Epic B           | Epic E             | Epic H              |
| Epic C           | Epic F             |                     |
```

**Quien lo usa**: Empresas consumer tech sin deadlines duros (Google, Facebook, Twitter).

## Punto Clave

> Roadmaps trimestrales estan bien como **guia general** — pero dile a todos "esto puede cambiar." La forma agile es **Ahora / Siguiente / Despues**.

## Buzzwords

| Termino | Definicion |
|---|---|
| **Roadmap** | Plan de que se construye y aproximadamente cuando |
| **Epic** | Agrupacion de features que toma >1 sprint |
| **Story Points** | Medida de dificultad (no tiempo) asignada por ingenieros |
| **Velocity** | Promedio de story points completados por sprint |
| **Sprint Planning** | Reunion para definir trabajo y estimar story points |
| **Acceptance Criteria** | Condiciones testeables especificas que un feature debe satisfacer |
| **QA** | Quality Assurance — fase de pruebas antes de release |
