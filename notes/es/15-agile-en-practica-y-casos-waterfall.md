# 15 - Agile en Practica y Cuando Usar Waterfall

## Agile en Accion: Ejemplo de Streaming de Musica

```
Paso 1: Identificar feature mas importante → Playlist
Paso 2: Definir requisito core → Agregar tracks a una lista

    Ingenieros                  PM + Disenador
    ----------                  ---------------
    Construir base de     →     Wireframes de disenos
    datos para playlists        Probar con usuarios
                                Iterar con feedback
                          ↓
    Implementar UI +      ←     Diseno final listo
    feature
                          ↓
    Ingenieros codean     →     PM + Disenador comienzan
    feature de playlist         a investigar SIGUIENTE feature
                                (el ciclo se repite)
```

**Clave**: Todos trabajan **en paralelo** y en **colaboracion cercana** (misma oficina, hablando siempre).

## Cuando Usar Waterfall

| Caso de Uso | Por que Waterfall Funciona Aqui |
|---|---|
| **Sistemas Operativos** (Windows, macOS) | Miles de features interdependientes — no puedes lanzar algunos solos |
| **Software critico** (frenos de auto, control de motor) | No puedes experimentar — debe estar 100% correcto antes de lanzar |
| **Construccion** (rascacielos, puentes) | No puedes construir 5 pisos y "probar" — construir los 100 desde un spec completo |

## Agile vs Waterfall: Dinamica de Equipo

| | Agile | Waterfall |
|---|---|---|
| **Colaboracion** | Muy cercana — misma sala, comunicacion constante | Equipos pueden estar en diferentes ciudades/zonas horarias |
| **Por que** | Feedback e iteracion continua | Todo definido de entrada, se pasa entre equipos |

## Conclusion

Como PM usaras mayormente **Agile**, pero Waterfall no es inutil — es la herramienta correcta para situaciones especificas.
