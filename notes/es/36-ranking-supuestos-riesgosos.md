# 36 - Ranking de Supuestos Riesgosos (MVP Paso 2b)

## Por Que Rankear por Riesgo?

Probar los supuestos mas riesgosos **primero**. No desperdicies recursos validando los faciles solo para fallar en el supuesto #6 y tirar todo.

## Ranking de Riesgo de los 4 Supuestos Comunes

| Rank | Supuesto | Nivel de Riesgo | Por que |
|---|---|---|---|
| **1 (mas alto)** | Mi cliente tiene el problema X | **Critico** | Si el problema no existe, estas construyendo una solucion buscando un problema — game over |
| **2** | [X] le importa a mis clientes | **Alto** | Obstaculo, pero marketing puede convencer a la gente de que les importe algo nuevo (Domino's 30 min, HDTV) |
| **3** | No hay sustitutos satisfactorios | **Medio** | La gente puede ser desplazada de sustitutos si muestras algo mejor (feature phones → iPhone) |
| **4 (mas bajo)** | Los usuarios pagaran/se registraran | **Menor** | Problema para modelo de negocio, pero hay alternativas (ads, freemium, monetizacion indirecta) |

## La Regla

```
Empieza con el supuesto que, si es falso, hace que TODOS los demas sean irrelevantes.
    → Ese es tu objetivo #1 para el experimento MVP.
    → Despues de validarlo, pasa al siguiente mas riesgoso.
```

## Punto Clave

> Una solucion buscando un problema **nunca funciona bien**. Siempre valida que el problema exista antes que cualquier otra cosa.
