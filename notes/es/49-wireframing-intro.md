# 49 - Wireframing: Introduccion

> Nuevo capitulo: Conceptualizando Tus Ideas

## Que es un Wireframe?

Una **guia visual** que establece la estructura aproximada de donde va el contenido en un sitio web, web app o mobile app. Es la **primera traduccion cruda** de una idea de producto.

## Por Que Hacer Wireframes?

En la fase de diseno, todo es abstracto y verbal. Wireframing es el primer paso para hacerlo **definido y preciso**.

## Baja Fidelidad → Alta Fidelidad

```
Baja Fidelidad                  →                    Alta Fidelidad
Circulo que dice "boton"        →    Boton disenado que dice "Registrarse"
Texto garabateado / Lorem Ipsum →    Copywriting terminado
Sketch de layout general        →    Diseno grafico completo, parece funcional
```

| Nivel | Detalle | Proposito |
|---|---|---|
| **Baja fidelidad** | Muy basico, creado rapido | Probar conceptos amplios, definir vision general |
| **Media fidelidad** | Mas detalle, contenido aproximado | Recopilar feedback, refinar layout y flujo |
| **Alta fidelidad** | Diseno completo, se ve real | Mockup final antes de desarrollo — dificil saber que no es funcional |

## El Proceso Iterativo

```
Sketch amplio → Investigacion/feedback → Agregar detalle → Mas feedback → Mas detalle → ... → Alta fidelidad
```

## Los PMs Hacen Wireframes?

| Tamano de org | Rol del PM en wireframing |
|---|---|
| **Startup** | Si — all hands on deck, haras wireframes |
| **Mediana** | A veces — sentarse con disenadores, contribuir juntos |
| **Gran empresa** | Se espera familiaridad — hacer sketches para proponer ideas, pero los disenadores hacen el trabajo pulido |

## Conclusion

No necesitas ser un guru de UX. Necesitas **comunicar ideas de producto complejas visualmente** y, en caso de emergencia, hacer wireframes tu mismo.
