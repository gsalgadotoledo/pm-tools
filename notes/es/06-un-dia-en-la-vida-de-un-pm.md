# 06 - Un Dia en la Vida de un PM

## Dia Tipico (Hora por Hora)

| Hora | Actividad | Categoria |
|---|---|---|
| **9:00 AM** | Revisar emails + noticias tech | Awareness de Industria |
| **10:00 AM** | Revisar dashboard de metricas, cruzar con release logs | Metricas & Analisis |
| **10:30 AM** | Leer feedback de usuarios: emails de soporte, app store reviews, foro beta | User Research |
| **11:00 AM** | Standup del equipo (10-15 min): en que trabajamos, completado, blockers | Sync del Equipo |
| **11:15 AM** | Trabajar con disenador en problemas de usuario, whiteboard de soluciones | Discovery & Diseno |
| **12:00 PM** | Escribir specs, tickets, user stories, insertar wireframes | Planeacion & Documentacion |
| **1:00 PM** | Probar alpha release en Android + iOS, reportar bugs en Jira | QA & Testing |
| **2:00 PM+** | Varia por dia (ver abajo) | Reuniones & Colaboracion |

## Actividades de la Tarde (Varian)

| Dia/Contexto | Actividad |
|---|---|
| **Lunes** | Sprint planning, sprint grooming, o retrospectiva |
| **Mayoria de dias** | Reuniones cross-team con otros PMs o stakeholders |
| **Frecuente** | Reunirse con data science para revisar resultados de tests y comportamiento de usuarios |
| **Frecuente** | Asistir a user tests de nuevos features |
| **Frecuente** | Presentar metricas/milestones a ejecutivos e inversionistas |
| **Viernes** | Demo de logros del equipo a toda la empresa |
| **Segun necesidad** | Open houses para Q&A de toda la empresa con el equipo |
| **Segun necesidad** | Onboarding de nuevos empleados sobre vision y direccion del producto |

## Las 3 Cosas Que Nunca Cambian

1. Revisar **noticias de la industria** y **emails**
2. Revisar **metricas**
3. Reunirse con **tu equipo**

## Buzzwords

| Termino | Definicion |
|---|---|
| **Standup** | Reunion diaria corta donde el equipo comparte progreso y blockers |
| **Sprint Board** | Tablero visual mostrando tareas del sprint y su estado |
| **Backlog** | Lista priorizada de features/tareas esperando ser trabajadas |
| **Sprint Planning** | Reunion para decidir que trabajo entra en el siguiente sprint |
| **Sprint Grooming** | Refinar y estimar items del backlog antes del sprint planning |
| **Retrospective** | Reunion para revisar que salio bien/mal en el ultimo sprint |
| **Specs** | Especificaciones — descripcion detallada de que construir |
| **User Stories** | Descripciones de features desde la perspectiva del usuario ("Como usuario, quiero...") |
| **Wireframes** | Bocetos visuales de baja fidelidad del layout de un feature |
| **Alpha Release** | Version de prueba interna (antes de beta) |
| **Beta** | Version pre-release probada por un grupo limitado de usuarios reales |

## Herramientas y Recursos

| Herramienta/Recurso | Usado para |
|---|---|
| **Jira** | Herramienta de product management / bug tracking |
| **Techmeme** | Agregador de noticias tech |
| **Hacker News** | Comunidad tech + noticias |
| **Launch Ticker** | Noticias de lanzamientos de startups/productos |
| **Product Hunt** | Descubrir nuevos productos y features |
| **Twitter/X** | Monitorear que dice la gente sobre tu producto |
| **App Store Reviews** | Feedback directo de usuarios en releases mobile |
| **Metrics Dashboard** | Rastrear KPIs y detectar anomalias |
