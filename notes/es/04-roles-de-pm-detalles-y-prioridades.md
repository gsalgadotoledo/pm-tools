# 04 - Roles de PM: Detalles y Prioridades

## Internal Product Manager (PM Interno)

| Aspecto | Detalle |
|---|---|
| **Ideal para** | Personas que estan comenzando en product management |
| **Usuarios** | Solo personas dentro de tu empresa (marketing, ventas, etc.) |
| **Nivel de riesgo** | Bajo — un feature con bugs no le costara mucho dinero a la empresa |
| **Enfoque de aprendizaje** | Tecnologia — integrar con sistemas internos y herramientas de terceros |
| **Dia a dia** | Mucho **project management** |
| **Plataformas** | Generalmente una o muy pocas |

**Herramientas con las que trabajaras**: software de marketing, **CRMs**, sistemas internos.

---

## B2B / SaaS Product Manager

| Aspecto | Detalle |
|---|---|
| **Ideal para** | Tambien buena introduccion al PM |
| **Usuarios** | Cientos a miles de empresas (no millones de usuarios individuales) |
| **Nivel de riesgo** | Medio |
| **Flexibilidad** | Mas creativo en **como** construyes, menos flexible en **que** construyes |
| **Quien define prioridades?** | Fuertemente influenciado por **ventas** y potencial de ingresos |
| **Deadlines** | Mas ajustados — atados a **deals de ventas** con fechas limite |
| **Plataformas** | Generalmente una o muy pocas |

**Dinamica clave**: Ventas dice "el feature X traera $Y" — eso define tu roadmap.

---

## B2C / Consumer Product Manager

| Aspecto | Detalle |
|---|---|
| **Ideal para** | Personas que toleran **incertidumbre** y **presion** |
| **Usuarios** | Millones o decenas de millones |
| **Nivel de riesgo** | Alto — bugs pueden causar perdida masiva de usuarios e ingresos |
| **Flexibilidad** | Alta en que construir, pero debes validar con datos |
| **Quien define prioridades?** | Nadie te dice — lo descubres con investigacion y testing |
| **Deadlines** | Atados a **ciclos de release** |
| **Plataformas** | Multiples — Web, iOS, Android |
| **Aprendizaje** | Amplio — desde desarrollo web hasta desarrollo mobile |

**Dinamica clave**: Testing extensivo, analisis constante de feedback, **iteracion agile**.

---

## Comparacion Rapida

| | Internal | B2B/SaaS | B2C |
|---|---|---|---|
| **Tamano de usuarios** | Decenas/cientos | Cientos/miles de empresas | Millones |
| **Riesgo si algo falla** | Bajo | Medio | Alto |
| **Quien define prioridades** | Necesidades internas | Ventas + ingresos | User research + datos |
| **Libertad creativa** | Baja | Media (como, no que) | Alta (pero hay que validar) |
| **Plataformas** | 1 | 1-2 | Multiples (Web, iOS, Android) |
| **Buen punto de entrada?** | Si | Si | Desafiante |
| **Nivel de presion** | Bajo | Medio | Alto |

## Buzzwords

| Termino | Definicion |
|---|---|
| **CRM** | Customer Relationship Management — software para gestionar relaciones con clientes (ej: Salesforce) |
| **Agile** | Metodologia de desarrollo iterativa — construir, probar, aprender, repetir en ciclos cortos |
| **Release Cycle** | El periodo programado para lanzar nuevas versiones del producto |
| **Roadmap** | El plan de que features/productos se construiran y cuando |
| **Iterate** | Refinar repetidamente un feature basado en feedback y datos |

---

## Herramientas y Tecnicas

| Herramienta/Tecnica | Contexto |
|---|---|
| **CRMs** (Salesforce, HubSpot) | PMs internos y B2B integran con estos para gestionar datos de clientes |
| **Integraciones con terceros** | PMs internos conectan herramientas internas con servicios externos |
| **Metodologia Agile** | PMs B2C iteran y prueban rapidamente para descubrir que construir |
| **User testing** | PMs B2C dependen de probar con usuarios reales antes de lanzar |
| **Feedback loops** | PMs B2C revisan continuamente feedback para informar prioridades |
| **Project management** | PMs internos dedican tiempo significativo a flujos de gestion de proyectos |
