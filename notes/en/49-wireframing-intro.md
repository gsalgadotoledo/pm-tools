# 49 - Wireframing: Introduction

> New chapter: Conceptualizing Your Ideas

## What is a Wireframe?

A **visual guide** that lays out the rough structure of where content goes in a website, web app, or mobile app. It's the **first rough translation** of a product idea.

## Why Wireframe?

In the design phase, everything is abstract and verbal. Wireframing is the first step to make it **definite and precise**.

## Low Fidelity → High Fidelity

```
Low Fidelity                    →                    High Fidelity
Circle that says "button"       →    Designed button that says "Sign Up"
Scribble text / Lorem Ipsum     →    Actual finished copywriting
Broad sketch layout             →    Full graphic design, looks functional
```

| Level | Detail | Purpose |
|---|---|---|
| **Low fidelity** | Very basic, created quickly | Test broad concepts, define overall vision |
| **Medium fidelity** | More detail, rough content | Gather feedback, refine layout and flow |
| **High fidelity** | Full design, looks real | Final mockup before development — hard to tell it's not functional |

## The Iterative Process

```
Broad sketch → User research/feedback → Add detail → More feedback → Add more detail → ... → High fidelity
```

## Do PMs Wireframe?

| Org size | PM's wireframing role |
|---|---|
| **Startup** | Yes — all hands on deck, you'll wireframe |
| **Mid-size** | Sometimes — sit with designers, contribute together |
| **Large company** | Familiarity expected — sketch ideas to propose, but designers do the polished work |

## Bottom Line

You don't need to be a UX guru. You need to **communicate complex product ideas visually** and, in a pinch, sketch wireframes yourself.
