# 06 - A Day in the Life of a PM

## Typical Day (Hour by Hour)

| Time | Activity | Category |
|---|---|---|
| **9:00 AM** | Check emails + tech news | Industry Awareness |
| **10:00 AM** | Review metrics dashboard, check release logs for anomalies | Metrics & Analysis |
| **10:30 AM** | Read customer feedback: support emails, app store reviews, beta forum | User Research |
| **11:00 AM** | Team standup (10-15 min): what we're working on, completed, blockers | Team Sync |
| **11:15 AM** | Work with designer on user problems, whiteboard solutions | Discovery & Design |
| **12:00 PM** | Write specs, tickets, user stories, insert wireframes | Planning & Documentation |
| **1:00 PM** | Test alpha release on Android + iOS, file bugs in Jira | QA & Testing |
| **2:00 PM+** | Varies by day (see below) | Meetings & Collaboration |

## Afternoon Activities (Varies)

| Day/Context | Activity |
|---|---|
| **Monday** | Sprint planning, sprint grooming, or retrospective |
| **Most days** | Cross-team meetings with other PMs or stakeholders |
| **Frequent** | Meet with data science to review test results and user behavior |
| **Frequent** | Attend user tests of new features |
| **Frequent** | Present metrics/milestones to executives and investors |
| **Friday** | Demo team accomplishments to the company |
| **As needed** | Open houses for company-wide Q&A with the team |
| **As needed** | Onboard new employees on product vision and direction |

## The 3 Things That Never Change

1. Check **industry news** and **emails**
2. Review **metrics**
3. Meet with **your team**

## Buzzwords

| Term | Definition |
|---|---|
| **Standup** | Short daily meeting where the team shares progress and blockers |
| **Sprint Board** | Visual board showing current sprint tasks and their status |
| **Backlog** | Prioritized list of features/tasks waiting to be worked on |
| **Sprint Planning** | Meeting to decide what work goes into the next sprint |
| **Sprint Grooming** | Refining and estimating backlog items before sprint planning |
| **Retrospective** | Meeting to review what went well/badly in the last sprint |
| **Specs** | Specifications — detailed description of what to build |
| **User Stories** | Feature descriptions from the user's perspective ("As a user, I want...") |
| **Wireframes** | Low-fidelity visual sketches of a feature's layout |
| **Alpha Release** | Internal test version (before beta) |
| **Beta** | Pre-release version tested by a limited group of real users |

## Tools & Resources

| Tool/Resource | Used for |
|---|---|
| **Jira** | Product management / bug tracking tool |
| **Techmeme** | Tech news aggregator |
| **Hacker News** | Tech community + news |
| **Launch Ticker** | Startup/product launch news |
| **Product Hunt** | Discover new products and features |
| **Twitter/X** | Monitor what people say about your product |
| **App Store Reviews** | Direct user feedback on mobile releases |
| **Metrics Dashboard** | Track KPIs and detect anomalies |
