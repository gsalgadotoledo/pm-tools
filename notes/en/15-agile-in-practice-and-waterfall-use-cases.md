# 15 - Agile in Practice & When to Use Waterfall

## Agile in Action: Music Streaming Example

```
Step 1: Identify most important feature → Playlist
Step 2: Define core requirement → Add tracks to a list

    Engineers                    PM + Designer
    --------                    -------------
    Build database        →     Wireframe designs
    for playlists               Test with users
                                Iterate on feedback
                          ↓
    Implement UI + feature ←    Final design ready
                          ↓
    Engineers coding       →    PM + Designer start
    playlist feature            researching NEXT feature
                                (cycle repeats)
```

**Key**: Everyone works **in parallel** and in **close collaboration** (same room/office, always talking).

## When to Use Waterfall

| Use Case | Why Waterfall Works Here |
|---|---|
| **Operating Systems** (Windows, macOS) | Thousands of interdependent features — can't release a few standalone |
| **Mission-critical software** (car braking, engine control) | Can't experiment — must be 100% right before release |
| **Construction** (skyscrapers, bridges) | Can't build 5 floors and "test" — build all 100 from a complete spec |

## Agile vs Waterfall: Team Dynamics

| | Agile | Waterfall |
|---|---|---|
| **Collaboration** | Very close — same room, constant communication | Teams can be in different cities/time zones |
| **Why** | Continuous feedback and iteration | Everything defined upfront, passed between teams |

## Bottom Line

As a PM you'll mostly use **Agile**, but Waterfall isn't useless — it's the right tool for specific situations.
