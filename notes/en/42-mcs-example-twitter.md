# 42 - MCS Example: Twitter Link Preview Feature

## The Process: Cost vs Reward

Start with the **left side (cost)** — it's based on facts. Right side is more speculative.

## Example: Adding Link Hover Pop-up to Twitter

### Left Side: Cost

| Cost item | Calculation |
|---|---|
| 2 developers × 2 weeks | $100K/yr ÷ 12 = ~$8K/mo → $4K each × 2 = **$8,000** |
| PM time (part-time, 2 weeks) | **$2,000** |
| Ads to announce/drive traffic | **$3,000** |
| **Total cost** | **$13,000** |
| **Opportunity cost** | 2 weeks those devs could have fixed bugs or built something else |

### Right Side: Expected Reward

Pick **one metric** (two becomes confusing). Think about what it means to the business.

| Scenario | MCS calculation |
|---|---|
| **Revenue effect** | If this raises conversion from free→paid by X%, does that generate more than $13K? |
| **Goal alignment** | If yearly goal is +40% avg minutes consumed, we need ~4% monthly improvement to stay on track (1 month of dev = 1 month of the goal) |

## Rules of Thumb

- **Big risks need big rewards**, small risks are okay with small rewards
- Pick **one metric** — two is too confusing to verify success
- Think **past the metric** — if time-on-site increases, that means ad revenue increases
- Start with left side (cost) — it's easier and more concrete
- This is **napkin math** — don't calculate to the penny, but don't be lazy either
- Align to a **bigger company goal** if possible

## The MCS Statement

> "If it costs $X, we need to see Y improvement in [metric] to justify going ahead."
