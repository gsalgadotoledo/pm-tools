# 31 - MVPs (Minimum Viable Product)

> New chapter: MVPs

## What is an MVP?

The **smallest amount** of a proposed product you can build to get **real feedback** about whether users are actually interested.

> MVP is a **process** (an experiment), not a prototype.

## The MVP Experiment

```
Assumption → Hypothesis → Minimum criteria for success → Test → Learn
```

| Concept | Definition |
|---|---|
| **Validated Learning** | Learning from customers in an unbiased test environment where they act naturally |
| **Learning** | Anything else — not designed like an experiment, results can't be trusted |

## The Path Metaphor

```
You're at a fork with 3 paths. Townspeople SAY they know the way.
    → Don't trust opinions (subjective, qualitative)
    → Walk down each path just far enough to see if it's right
    → Minimum effort to validate direction = MVP
```

## Classic Example: Zappos

| Traditional approach | MVP approach (what Zappos did) |
|---|---|
| Build fancy website | Make a basic website |
| Buy inventory | Take photos at a local shoe store |
| Hire programmers | When someone bought, physically buy the shoe and ship it |
| Hope people want it | **Validated** that people will buy shoes online |

## Why MVPs?

| Reason | Detail |
|---|---|
| **Idea validation** | Know if people want it BEFORE building it fully |
| **Risk mitigation** | Cheaper to test with a Google form than build a full platform |
| **Speed** | Fail fast → run more experiments → find what works faster |
| **Save resources** | Time, money, opportunity cost |

## Common Misconception

MVP ≠ prototype or basic version of your product. MVP = **whatever it takes to validate the idea**, which often means **building almost nothing**.

## The "Fail Fast" Mantra

```
Faster MVP experiments → More experiments in same time → More data → Better decisions
```

## Buzzwords

| Term | Definition |
|---|---|
| **MVP** | Minimum Viable Product — smallest thing to validate an idea |
| **Validated Learning** | Learning from unbiased customer testing in natural conditions |
| **Fail Fast** | Run quick experiments so failures happen early and cheaply |
| **Hypothesis** | Your assumption about what users want, to be tested |
